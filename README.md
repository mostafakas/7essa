# حصّة — منصة إدارة السناتر والدروس الخصوصية

منصة SaaS مبنية على دراسة الجدوى المرفقة: سنتر كامل أو مدرس خاص يدير الحضور بالـQR، الخزنة والإيصالات، تسويات المدرسين، الامتحانات الإلكترونية، وولي الأمر يتابع كل شيء من حساب واحد حتى لو ابنه في أكثر من مكان.

| الجزء | التقنية |
|---|---|
| الخادم | NestJS 11 + TypeScript (strict) |
| قاعدة البيانات | PostgreSQL 16 مع عزل الصفوف (RLS) + Prisma 6 |
| الطوابير | Redis 7 + BullMQ (الإشعارات) |
| الواجهة | Next.js 15 + React 19، عربية بالكامل RTL |
| التشغيل | Docker Compose، ‏Node 22 |

---

## التشغيل لأول مرة (بيئة التطوير)

المتطلبات: Node.js 22 أو أحدث، وDocker Desktop.

```bash
# 1) تثبيت الحزم (ينشئ package-lock.json)
npm install

# 2) إنشاء ملف .env بأسرار عشوائية قوية
npm run setup:env

# 3) تشغيل PostgreSQL وRedis
npm run db:up

# 4) إنشاء الجداول + سياسات الأمان + بيانات تجريبية
npm run db:setup

# 5) تشغيل الخادم والواجهة (كل واحد في نافذة طرفية)
npm run dev:api
npm run dev:web
```

افتح <http://localhost:3000>.

**رمز الدخول في وضع التطوير يظهر في نافذة الخادم** (سطر «رمز الدخول للرقم …»)، لأن مزود الرسائل غير مربوط بعد. في الإنتاج يرفض الخادم الإرسال حتى يُربط مزود حقيقي.

### حسابات البيانات التجريبية

| الدور | الرقم |
|---|---|
| مالك المنصة | 01000000000 |
| مالك السنتر (سنتر النور) | 01000000001 |
| الاستقبال | 01000000002 |
| المحاسب | 01000000003 |
| مدرس فيزياء | 01000000004 |
| مدرسة إنجليزي | 01000000005 |
| مساعد مدرس الفيزياء | 01000000006 |
| مدرس خاص (رياضيات) | 01000000007 |
| ولي أمر (ابن في السنتر وعند المدرس الخاص) | 01100000001 |

جرّب بالترتيب:

1. ادخل بالاستقبال، وافتح «الحضور عند الباب».
2. اكتب كود أي طالب من صفحة «الطلاب» وشاهد الختم.
3. افتح «الخزنة» وافتح وردية، ثم حصّل مبلغًا واطبع الإيصال.
4. ادخل بولي الأمر لترى الابن في مكانين بهوية واحدة، والـQR المتغير، والامتحان المتاح.
5. ادخل بالمالك وشاهد «الموافقات» (طلب إلغاء معلق ووردية بعجز)، ثم «التسويات» واحسب الشهر السابق.
6. ادخل بمدرس الفيزياء لتأكيد كشف حسابه.

### تشغيل كامل بالحاويات

نفّذ خطوات التطوير 1–4 مرة واحدة أولًا؛ فهي تنشئ مجلد `apps/api/prisma/migrations` الذي تطبقه حاوية الخادم تلقائيًا عند كل تشغيل. أوقف بعدها `dev:api` و`dev:web` إن كانا يعملان، ثم:

```bash
docker compose --profile full up --build
```

ارفع مجلد `migrations` إلى المستودع؛ فهو سجل تغييرات قاعدة البيانات الذي يُطبق في الإنتاج.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm test` | اختبارات الوحدات (المال، التسويات، الـQR، التصحيح، الجدولة، المتأخرات) |
| `npm run typecheck` | فحص الأنواع للخادم والواجهة |
| `npm run build` | بناء نسخة الإنتاج |
| `npm run db:seed -w apps/api -- --force` | إضافة البيانات التجريبية فوق الموجود |

```
│  │  │  └─ notifications/     طابور الإشعارات
│  │  └─ test/                 اختبارات الوحدات
│  └─ web/                     الواجهة
│     └─ src/app/
│        ├─ login, start       الدخول وإنشاء مساحة العمل
│        ├─ app/…              بوابة السنتر والمدرس (13 صفحة)
│        ├─ family/…           بوابة الأسرة
│        ├─ platform/          إدارة المنصة
│        └─ print/…            الإيصال الحراري والكارنيه
├─ docs/                       الأمان، المعمارية، مرجع الـAPI، خارطة الطريق
├─ docker/postgres/init/       إنشاء دور التطبيق المقيد
└─ docker-compose.yml
```

## قبل الإطلاق للإنتاج

- [ ] ربط مزود SMS أو WhatsApp في `apps/api/src/auth/sms.provider.ts`، مع إلغاء طباعة الرمز في السجل.
- [ ] ربط قنوات الإشعارات الفعلية (FCM، واتساب) في معالج الطابور.
- [ ] `COOKIE_SECURE=true` و`NODE_ENV=production` وتشغيل خلف HTTPS، مع ضبط `WEB_ORIGIN` على النطاق الفعلي.
- [ ] نسخ احتياطي يومي مشفر لقاعدة البيانات، واختبار الاسترجاع.
- [ ] تنفيذ `npm run db:deploy -w apps/api` عند كل نشر (بحساب المالك).
- [ ] مراجعة أمنية خارجية واختبار اختراق قبل استقبال بيانات حقيقية.
- [ ] مراجعة قانونية لسياسة الخصوصية وموافقة أولياء الأمور وفق قانون حماية البيانات الشخصية المصري 151 لسنة 2020.

التفاصيل في [`docs/security.md`](docs/security.md) و[`docs/roadmap.md`](docs/roadmap.md).
